## D1 — Challonge auth model: **OAuth2 Connect client-credentials** (closes the [BLOCKING] item)
v1 sync uses **Challonge Connect OAuth2 client-credentials**, NOT the legacy
`CHALLONGE_API_KEY`. This is already implemented (`internal/challonge/client.go`) and
**verified live in production** (2026-08-17): token exchange + an app-scoped JSON:API
call both succeed against the sandbox app.
- **Env:** `CHALLONGE_CLIENT_ID`, `CHALLONGE_CLIENT_SECRET`, `CHALLONGE_TOKEN_URL`
  (default `https://api.challonge.com/oauth/token`), `CHALLONGE_API_BASE`
  (default `https://api.challonge.com/v2`), `CHALLONGE_SCOPE` (must include
  `application:manage`). Secrets live only in `/etc/fifteenball/fifteenball.env`.
- **Token:** cached, refreshed at a 5-min expiry margin by re-running the
  client-credentials grant (no refresh_token needed).
- **Request recipe (verified):** `Authorization: Bearer <t>`, `Authorization-Type: v2`,
  `Content-Type: application/vnd.api+json`, `Accept: application/json`; app resources
  under `/v2/application/...`.
- **Idempotency:** outbox job handlers pass a deterministic key
  `challonge:{tournamentId}:{operation}:{localVersion}` on each side-effecting call.

## D2 — Public tournament visibility: **private by default** (closes the [NON-BLOCKING] item)
Tournaments are **private** unless a director explicitly sets `visibility='public'`.
`tournaments.visibility enum('private','public') NOT NULL DEFAULT 'private'`. Public
endpoints (`/api/v1/public/...`) return **404** for private tournaments. Conservative,
non-disruptive if revisited.

## D3 — Bootstrap / role provisioning (reaffirm 02-role-permission-matrix)
On first sign-in: allowlisted email (`ALLOWED_EMAILS`) → user created + granted the
bootstrap role **`system_admin`**, `pending_role=false`. Non-allowlisted email → user
created as **`viewer`** with `pending_role=true`; never auto-promoted on re-signin. Only
`system_admin`/`club_admin` may grant/revoke roles.

## D4 — Fixed state enums (from 03-state-machines / 05-schema-contract)
- **tournament:** `draft, registration_open, registration_closed, in_progress, completed, archived`
- **entrant:** `pending, registered, checked_in, eliminated, withdrawn, disqualified` (+ `archived_at` soft-delete)
- **match:** `scheduled, assigned, in_progress, completed, reopened`
- **outbox job:** `pending, processing, completed, dead_lettered`
- **challonge sync_state:** `not_synced, in_progress, synced, failed`

## D5 — API surface & migration approach
- All new domain routes are versioned under **`/api/v1/...`**; existing auth routes
  (`/api/auth/*`, `/api/me`, `/api/health`) stay as-is (health/auth are unversioned).
- The deployed DB holds only throwaway test rows (auth testing); migrations may DROP the
  unused `tables`/`assignments`/`challonge_exports*` from `0001_init.sql` and CREATE the
  contract schema fresh. Forward-only, ordered migrations under `server/migrations/`.
